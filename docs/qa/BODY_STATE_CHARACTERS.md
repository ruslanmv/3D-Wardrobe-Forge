# Bare body state: where each of the eight library characters stands

2026-11-16. Forge `claude/busy-hamilton-m2vq2f`. A status document, not an acceptance report.

**What this work did not do.** No bare body state of any library character was generated,
rendered, inspected or imported, and no adult-design review was written or simulated. The
result below is therefore the same for all eight: **BLOCKED**, each with its named blocker and
the action that removes it. Nothing here says, or implies, that any of these characters is or is
not clearly adult in design: that finding is a person's, on the exact file, and none is
recorded.

Each character's own working sheet (exact file, terms, the bones, expressions and face and hair a
delivered file is held to, the artist's deliverable, and the commands with her slug and hash) is in
`docs/qa/body-state-specs/`, generated by `tools/body_surface/asset_spec.py`, which also pre-flights
a delivered file offline.

## 2. The route for each

| Character | Route | What it needs first |
|---|---|---|
| AvatarSample A, B, C, VRoid Female, VRoid Male, Model Girl, Rinna | `body-bare-v1` (authored body only), on a deployment with `WARDROBE_ADULT_BODY_SURFACE=true` | A person's review of the exact source file, recorded under its SHA-256. For A, B, C and the two VRoid bodies also the operator's documentation of the right to modify |
| AvatarSample_O | **Not** `body-bare-v1`: it refuses (`body-incomplete-for-bare`) and that refusal is correct | The missing chest geometry from a licensed artist (specification below), which is a new file with a new hash, and then the same review of that file |

If a reviewer does **not** find a character clearly adult, or cannot say, that character gets no
bare state. The path then is a replacement or a redesign, not a second opinion from software:

- an original character **designed as an adult**, with that stated in the creator's brief and
  evident to a reviewer who has only the file and its clothed pictures;
- a written licence from its creator permitting modification and sexual expression, and for a
  VRM the same terms in the file's own meta (`allowExcessivelySexualUsage` / `sexualUssageName`,
  modification allowed);
- VRM 0.x or 1.0, full humanoid, expressions, a face and hair skinned to the head, and a body
  that is complete under separate clothing meshes (closed in every band `body-bare-v1` checks:
  upper, lower, both thighs, both shins);
- pinned in the library by SHA-256, declared by the operator, and reviewed as in
  `docs/qa/BARE_STATE_HANDOFF.md`.

### Artist specification: AvatarSample_O

Source: `vroid-avatar-sample-o.vrm`, SHA-256
`e5c0395b59b636e6e0731ba872f4885d1bf1b69eba5f2904e68c16bd105e1697` (VRM 1.0; file terms:
modification allowed with redistribution).

- Deliver the same character with a **complete authored body**: the chest surface that the
  author deleted under the dress restored as part of the body mesh, and the alpha-cut band of
  skin made solid, so that the body is closed in the upper band as well as the others.
- Change nothing else: every humanoid bone on the same node within 1 mm, every expression by
  name, face and hair vertex for vertex within 0.1 mm, the same VRM title and authors, VRM 1.0.
- Skin weights on the new surface continuous with the surrounding torso; UVs on the existing
  body material; no added detail the character's author did not make.
- Deliver the result as a VRM with its SHA-256 and the artist's written statement of rights.
  It is a new exact file: it is added to the library under its own pin and reviewed as such.
- Acceptance is mechanical after that: `body-bare-v1` builds from it without
  `body-incomplete-for-bare`, or a bare file made from it passes `body_state_import.check`.

(Forge's opt-in reconstruction, BR1, can fill O's upper band with a proxy patch. Its output is
tagged reconstructed and **is never registered**: serving it would need a review of the output
file, and that registry does not exist. It is not a substitute for the artist's file.)

## What unblocks a row

1. A reviewer takes the packet for that file (`review_packet.py --slug <slug> --out <private dir>
   --sheets <clothed pictures>`), reviews it, and commits their entry to
   `assets/body_surface/adult-design-reviews.json` under their own name. Only `clearly-adult`
   opens anything; any other finding sends the character to the replacement path above.
2. The operator documents the right to modify (five files) and turns the switch on for the
   deployment that builds.
3. The operator builds (`body-bare-v1`) or receives the artist's file, has the **output** file
   reviewed, imports it, issues a grant or capability, and runs the two driver commands.

No code change is needed for any of the three.
