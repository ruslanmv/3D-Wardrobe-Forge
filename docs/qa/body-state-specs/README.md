## The order, for every slot

1. The operator documents the creator's terms (each sheet, section 2).
2. A reviewer reviews the **exact source file** from the packet and records the finding in `assets/body_surface/adult-design-reviews.json` under their own name. `clearly-adult` → route 1. Anything else, or nothing → route 2. Software does not make or stand in for this finding.
3. The file is built or delivered, pre-flighted, and its **exact output** reviewed.
4. The operator imports it, issues a read grant, and runs the driver. A mannequin or fixture run is not acceptance for a slot.

## Route 1: the character, with a complete body

Per-character requirements are in each sheet (sections 4 to 6). Common to all: same VRM version, same title and authors, every humanoid bone on the same node within 1 mm, every expression, face and hair unchanged within 0.1 mm, no clothing left, the body closed in six bands, the creator's rights documented. Forge's own build adds no surface and no detail; what an artist adds is the artist's authored work and is what the output review is for.

## Route 2: a replacement character

For a slot whose character is not found clearly adult, or whose terms cannot be documented. The replacement is a different exact file and goes through the same order from step 1.

- **Design.** An original character designed as an adult, stated in the creator's brief, and recognisable as one to a reviewer who has only the file and its clothed pictures. If the reviewer is unsure, it is not this.
- **Rights.** A written licence from its creator permitting modification, redistribution to the operator's deployment and sexual expression; the same terms in the VRM's own meta (VRM 1.0: `allowExcessivelySexualUsage: true`, `modification` allowed; VRM 0.x: `sexualUssageName: Allow`). Provenance recorded where the file lands (`assets/library/`).
- **Structure.** VRM 1.0 preferred. A valid humanoid with the full bone set including fingers; the expression names of the slot it replaces; a face and hair skinned to the head; clothing as separate meshes over a body that is complete under them (not painted on the skin, not deleted under the clothes); under 64 MB.
- **Registration.** Pinned in `assets/library/models.json` by SHA-256, declared in `assets/library/policy.json` by the operator, reviewed as in step 2; then `asset_spec.py --slug <new slug>` writes its sheet. In the companion app: `vendor/avatars/`, `vendor/avatars/avatars.json`, `src/wardrobe/AvatarIdentity.js`.

## Pre-flight

```bash
python tools/body_surface/asset_spec.py --preflight --slug <slug> --candidate <file.vrm> \
    --state bare --sha256 <sha256>
```

The import's own verdict, offline. It prints the structural checks and the eligibility checks separately, so a file can be seen to be structurally accepted while its reviews are outstanding. Exit 0 only when the import would accept it as things stand.
