# Garment catalog for HomePilot Avatar

The HomePilot Customize view needs real garments with real preview images, not
stock photos. Forge already has the procedural shapes and rendering pipelines.
This integration exposes an inexpensive, browsable catalog plus a real async
generation endpoint. It does not touch the Together activity launcher.

## Source of truth

- Garments are JSON templates in assets/garment_templates.
- GET /v1/templates is the existing raw template API.
- GET /v1/catalog/garments groups public templates by category.
- Each preview is a fitted VRM on the same reference sample avatar, rendered
  using the existing Studio's VRM viewer (tools/gallery/render.mjs).
- These are *reference previews*, not standalone garment GLBs or guaranteed fits
  on different user avatars. Every user-generated outfit must pass fit validation.
- Missing previews show previewStatus=pending and previewUrl=null; never invent
  image links.
- The API reads pre-rendered files from assets/catalog/previews. GET calls
  must never start expensive jobs.

## Public endpoints

GET /v1/catalog/garments
GET /v1/catalog/garments?category=top
GET /v1/catalog/garments/{id}/preview
POST /v1/catalog/customize

All four are served by the existing FastAPI app and protected by its existing
API key/trusted-origin middleware. Customize uses its existing job limiter and
Orchestrator rather than a second generator.

GET /v1/catalog/garments returns schemaVersion, totalTemplates, visibleCount,
previewCount and grouped categories. Each garment includes id, name, category,
description, tags, silhouette, hem, sleeve, supportsColor, requiresAdult,
previewStatus, and previewUrl.

Default public listings omit adult-gated template categories and explicit
requiresAdult templates. includeRestricted=true needs an existing admin session
(X-Wardrobe-Admin) but grants metadata access only, not a policy bypass.
Restricted images are not generated by the public batch script.

### Customizing through NEXUS

NEXUS, in 3D-Avatar-Chatbot, can translate "make this top red" into a prompt,
a template ID and a color. Forge does NOT invoke its own LLM here: it uses the
existing deterministic planner, native or Blender engine, licensing and fitting.

Example request:

    POST /v1/catalog/customize
    Content-Type: application/json

    {
      "avatar": {"storageKey": "sources/abc123/current.vrm", "avatarId": "my-avatar"},
      "prompt": "Red cropped tee",
      "templateId": "top-crop-tee-v1",
      "color": "red",
      "options": {
        "renderPreview": true,
        "engine": "auto",
        "wardrobeId": "my-avatar",
        "baseBody": "replace-outer",
        "ensureFoundation": true
      }
    }

Returns HTTP 202 and jobId, status, statusUrl and eventsUrl, exactly like
POST /v1/generate. Follow those existing progress/events routes until complete.
Only then load the validated VRM via the chatbot's existing wardrobe controller.

Use the *current look VRM* as source for garment replacement. Replacing a
single garment while retaining all other styling requires careful baseBody
and layering settings plus validation of the resulting plan. Do not falsely
claim that all other layers will be unchanged by an arbitrary prompt.

## Render real WebP thumbnails offline

Prerequisites: same as tools/gallery/README.md:
- pip install -e '.[dev]' and Pillow
- make library to download and verify sample avatars
- Node Playwright with Chromium and working CDN access

Smoke test (two real garments):

    python tools/catalog/render_templates.py --ids top-crop-tee-v1 jeans-straight-v1

Build the public-safe library:

    python tools/catalog/render_templates.py --avatar avatar-sample-a

Outputs:

    assets/catalog/previews/<templateId>.webp
    assets/catalog/build-report.json

The renderer skips cached WebPs, skips restricted templates, requires real
generation success, fit passing and general rating, then calls the same
Studio viewer as the existing gallery. Output is resized to 480px width
and encoded as WebP quality 82. Review the images before release.

Commit approved assets into the Space repository or a deployed asset bundle;
local container files can disappear when a Space restarts.

## HomePilot Customize integration

- Load one category group at a time; cache metadata.
- Only show a clothing thumbnail where previewStatus=ready.
- Selecting a template changes draft state, not the real avatar.
- Confirm template, color and prompt, then queue a single Forge customize job.
- Show actual job progress and keep the currently worn outfit on failure.
- Load the returned VRM only when generation, fit and validation succeed.
- Keep all ten original TOGETHER activities and their lifecycle unchanged.
